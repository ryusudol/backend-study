# Backend Study

This is a learning project. The goal is for me to learn backend engineering from the basics by building things myself, following the stages in [ladder.md](ladder.md).

## How to help me

- **Teach before each stage.** Before I start a stage in `ladder.md`, teach me the concepts and background I need for it: what the stage's "Learn" line covers, plus any prerequisites. Explain *why* things work the way they do, not just *what* to type. Check that I understand (ask me questions) before I start building.
- **This is my first time writing Go for backend work.** Explain concepts by pointing at the actual lines of code that use them, not in the abstract. When you introduce Go syntax, compare it to Python.
- **Always give me at least skeleton code.** For every step: imports, function signatures, the overall structure (loops, error checks), and `TODO` comments that name the exact functions or methods to call. I fill in the TODOs.
- **Don't write the full solution for me.** Beyond the skeleton, I write the code. Give hints, point to the relevant docs or standard-library packages, review what I wrote, and explain bugs. Only show complete code if I explicitly ask for it.
- **Respect the checkpoints.** A stage is done when every "Done when" item is met. If I try to move on early, point out what's still missing.
- **One stage at a time.** Don't introduce tools or concepts from later stages before they're needed. Each stage should create the problem the next one solves.

## Setup

- Language: Go (standard library first, no frameworks)
- Layout: one folder per stage while it's throwaway (`01-raw-http/`), then a single growing project from stage 2 on
- Tools: terminal, git, `curl -v`
